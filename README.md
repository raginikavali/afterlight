# Afterlight – Urban Capacity

## What I built

I built **Afterlight**, a one-page interactive concept around the idea that cities already have a lot of space, but we don't use all of it all the time.

For example, a classroom, office, hall, or other building might be busy during the day but completely empty for a few hours later. Instead of always thinking about building more space, Afterlight looks at how the existing space can be used during those empty hours.

The main idea is **“The city has more space than it knows.”**

I made the page as a pitch for a decision-maker, so I focused on explaining the problem quickly and then showing how the idea could work.

## Key decisions I made

One of my main decisions was to make the website **interactive instead of just showing static information**. The time slider and map are important because when the time changes, the available spaces change. This helps explain the main idea of Afterlight without needing a lot of text.

I also kept the flow simple:

**OBSERVE → MATCH → USE**

The system first looks at available spaces, then matches them with a possible need, and finally the space can be used.

Another decision I made was to include an **Operator Review** instead of making the system completely automatic. Real spaces have restrictions like access, safety and permitted use, so I wanted to show that the system recommends options but a human still makes the final decision.

For the pitch, I also chose a **30-day pilot in one district** instead of suggesting that the whole city should immediately adopt the idea. I felt this made the concept more realistic and easier for a decision-maker to consider.

I also avoided adding too many pages or features because the task was about pitching one idea clearly. I wanted the website to feel like a focused product concept rather than a large application.

## Where AI gave me weak or wrong output

I used AI while working on the project, mainly for brainstorming, structuring the page, and improving some parts of the implementation. But I did not use the first output directly.

One problem was that the initial idea started becoming **too broad and overbuilt**. There were too many sections and features, which made the main idea less clear. I noticed that this was going against the requirement of having one strong idea and one convincing page.

I removed unnecessary sections and kept the parts that actually helped explain the concept: the problem, the time-based interaction, the matching process, operator review, and the 30-day pilot.

AI also sometimes suggested generic features or wording that sounded good but did not really help explain why Afterlight was different. I changed those parts to focus more on the idea of **time as another dimension of space**.

I also checked the implementation myself instead of assuming the generated code was correct. For example, I found an interaction where a button was pointing to an old section ID after I changed the page structure. I updated it to point to the correct section.

So, I used AI as a starting point, but I made the final decisions based on the internship requirements, the actual user experience, and by testing the page myself.
